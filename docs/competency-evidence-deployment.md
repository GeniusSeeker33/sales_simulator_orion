# Human-reviewed competency evidence — Issue #21

Related to GeniusSeeker33/geniusseeker-talent-success-platform#21. Implementation only; nothing in this change deploys a database migration or enables production access.

## Contract and boundaries

- One immutable UUID record represents **one competency, one exact source observation and one human finding**. Model version is pinned to `orion-sales/0.1-draft`, C01–C15; draft references do not activate employment policy. There is no numeric score, proficiency band, aggregation, progression or ranking.
- `publish_competency_evidence(p_id, p_scope, p_body)` derives binding/person/employment episode and reviewer `auth.uid()` server-side. The existing private authorization helper checks active, approved, unexpired reviewer scope for that exact binding on every operation. Writes also require an active target binding and a separate reviewer. Scope and binding locks serialize revocation against publication.
- `learner_competency.evidence` is private, RLS-enabled, with **no direct authenticated table access or write policies**. Explicitly granted invoker RPC wrappers call tightly scoped private definer implementations with empty search paths. No new credentials, roles based on email/name, browser secrets, service key or shared login.
- `read_competency_evidence(p_scope, p_before, p_before_id)` returns up to 51 records (50 displayed plus pagination sentinel). Learners omit scope and read only their current verified episode. Other assigned reviewers may read; outside/revoked/expired scopes fail even with an existing JWT. A separate active historical scope permits retired-episode reads, never writes. Rehires inherit neither references nor access.
- `ai_practice` identifies the existing simulator/practice context, including written exercises; it **does not assert that an AI assessment exists**. Preserve actual kind, status and assessment metadata when available. AI output remains unreviewed supporting evidence; the reviewer authors the observation/finding. Do not count attempt and its simulation session as independent corroboration.
- Practice references are terminal attempt or simulation UUID + revision, validated against the exact binding. Simulation references preserve the parent attempt ID. Coaching references must match the target competency/version and current completed coaching revision. Coaching retains underlying reference metadata, not narrative or response text. Publication locks the coaching source against concurrent correction. Once a source is corrected, existing findings retain the exact original reference and reads flag its successor; a human must reconsider and supersede as appropriate.
- `real_world_work` is reserved conceptually but rejected by the write RPC and disabled in the UI until a governed source validator is implemented. No arbitrary artifact URL or invented integration.
- Findings: `supports`, `does_not_yet_support`, `insufficient_opportunity`, `technical_failure`, `disputed`. Failed/abandoned practice cannot produce either support finding. The latter three states remain non-scored; no conversion to zero or proficiency inference. Human coaching conclusions are reviewed observations, not automatic promotion of underlying AI evidence.
- Corrections require the original reviewer, active exact-episode scope, latest predecessor and a reason. A new UUID increments revision and uniquely supersedes its predecessor; update/delete triggers preserve history. Other reviewers may create their own attributable observation but cannot overwrite another's. Idempotent retries require the same UUID/scope/body and recheck authorization. New publications reject stale sources; an exact replay returns the existing receipt without creating a new finding.
- Only minimum source IDs, revisions, system/entity/environment/project context and concise reviewer-authored summary are stored. No transcripts, recordings, raw AI feedback, private artifacts or personnel lookups. Summary text is learner-visible; reviewers must not paste restricted material. No local storage of findings or drafts. Legacy unattributed browser records remain quarantined and cannot serve as source IDs.

## Verification

`npm run test:learner` executes all four actual migrations in isolated PGlite PostgreSQL with authenticated/anonymous roles and JWT subject fixtures. Includes durable disk restart, authorized/outside/revoked/expired scope cases, own-learner visibility and write denial, stale source revision and superseded coaching rejection, competency target validation, wrong episode, rehire, correction lineage, non-scored failure/dispute/opportunity states, pagination, unchanged band/level sentinels and legacy quarantine regression. No hosted database was contacted. PGlite does not exercise Supabase JWT gateway/PostgREST or concurrent multi-connection locking; those remain staging checks.

Browser acceptance in staging:

1. As reviewer, open **Assigned Learner History**, choose A's exact episode, review a terminal attempt/simulation or completed coaching version. In **Episode competency evidence**, enter that exact ID/revision, a single C01–C15, date, concise observation and finding. Publish; refresh/new session must retrieve the same UUID and reviewer identity.
2. As A, open **My Coaching** to read findings; no publish/correct controls. B and outside reviewer cannot retrieve A's findings, including by calling the RPC directly. Test expired and revoked scopes with the same still-authenticated browser and on older pages. Refresh/focus/poll checks remove unavailable displayed history; server authorization applies on every request.
3. Try wrong-episode, stale revision and corrected coaching IDs; publication must fail. Correct a source coaching session and verify an existing finding flags the source successor. Review that successor before publishing a corrected finding.
4. Publish a technical-failure/disputed/insufficient-opportunity finding; verify no score or level appears or changes. Attempt `does_not_yet_support` on failed practice: rejected. Correction preserves original finding, author, reason and revision chain.
5. Retire A's old binding and provision a distinct rehire binding. A's self-view now shows only the new episode; old scopes cannot create records or import old references into it. Confirm historical reviewer reads require the explicitly assigned old binding.
6. In staging, exercise simultaneous source correction/publication and reviewer revocation/publication from separate sessions. Check the serialized result and ensure no new publication succeeds using an already committed revocation or supersession. Do not treat a request completed before revocation as a failed authorization.

Open operational decisions: approve the pinned draft competency version for pilot references, reviewer scope ownership/expiry, original-reviewer-unavailable correction escalation, retention/access review policy and any future governed real-world evidence source. None authorizes proficiency or progression automation.
